# 흐름 검증 기록 — 첫 캐릭터

- 키트: Charakuru 1.0.4 (배포원 Release ZIP). 키트 코드는 수정하지 않았고, 보조 스크립트를 키트 밖에 두어 보강했다.
- 환경: Windows 10, Chrome, Blender 5.2 + VRM Add-on + Blender MCP, Tripo 계정.
- 역할: 사용자 = 최종 판단, 리드 에이전트(Claude Code) = 계획·검수, 작업 에이전트(Codex) = 이미지·브라우저 작업.
- 검증일: 2026-10-19

## 1. 끝낸 범위

원본 삼면도 → 머리 4장 + 몸 4장 이미지 → Tripo 후보(머리/몸) → 부위 분류 → 4K 재텍스처 → UV 복원 →
MToon 조립 → 비율 조정 → Tripo 리깅 → 웨이트 전송 → 스프링 18체인 → VRM 1.0 내보내기 → Warudo에서 열림.

Tripo 크레딧: 후보 200, 세그먼트/UV/재텍스처 200, 리깅 20. 합계 약 420.

## 2. 흐름에서 문제였던 것

1. **머리 이미지가 컨셉 아트보다 짧았다.** 뒤/옆 이미지가 가슴 높이에서 끝나 3D도 짧게 나왔다. 이미지 단계에서
   컨셉 아트의 길이·볼륨을 비교 검수하는 항목이 필요하다.
2. **머리카락 판 사이 틈과 안쪽 겹층.** 판 겹침 구조라 가닥 사이로 아래층이 비친다. 메시를 고치는 후처리(길이 연장,
   가닥 복사, 정점 합치기)는 각진 판을 만들었고, **색(텍스처 좌표)만 바꾸는 후처리가 안전했다.**
3. **머리 모델 뒤쪽/턱 아래가 열린 껍질.** 머리를 끄면 비어 있다. 명시된 한계로 문서화가 필요하다.
4. **웨이트 전송이 옷을 다리 본에 묶었다.** 후디 몸통(옆구리 약 70%, 아랫단 100%)이 upper_leg에 연결돼 걸을 때
   상하체가 어긋났다. 리깅 직후 **옷 몸통 웨이트 검사**(높이별 우세 본)가 필요하다.
5. **넓은 후디가 일반 애니메이션과 맞지 않는다.** 팔이 몸통을 파고들고 후드 뒤 볼륨을 머리카락이 통과한다.
   후드 볼륨 상한을 정하거나 줄이는 단계가 필요하다(20% 축소가 효과적이었다).
6. **스프링 체인 8줄 치마.** 줄끼리 독립이라 주름이 벌어진다. 줄 수(16+)를 늘리거나 다리 추종 웨이트와 섞어야 한다.
   키트 검사는 흔들림 본에 정점이 연결돼 있어야 통과한다(다리 추종만으로는 거부).
7. **충돌체 설계.** 구 하나로는 허벅지/어깨를 막지 못한다. 허벅지·어깨·목은 캡슐, 윗가슴 앞에 구가 필요했다.
   빠른 동작은 반경과 강성·감쇠를 올려야 한다.
8. **얼굴 UV 조각남.** Smart UV가 얼굴을 여러 섬으로 쪼개 눈/입 영역이 텍스처 전체에 흩어져 표정 텍스처 작업이 어렵다.
9. **표정이 없다.** 키트 문서대로 일반 얼굴·시선 고정이다. VRM 표정 항목은 이름만 있고 데이터가 비어 있다.
10. **VRM 1.0만 나온다.** VSeeFace는 0.x만 열어 `NotVrm0Exception`. Warudo 등에서는 열린다.
11. **앱 연결 오류.** 요청을 만든 탭의 client id가 어긋나면 begin이 「最新状態を取得できませんでした」로 실패했다.
    새 요청을 만들고 로컬 checkpoint를 감시하는 방식으로 우회했다.
12. **프로젝트 파일 크기.** 내보내기 후 약 84MB → 590MB로 커졌다.

## 3. 다음 캐릭터에서 바꿀 것 (우선순위)

1. 이미지 단계: 컨셉 아트와 길이·볼륨·색 비율 비교 검수. 후드·긴 머리처럼 볼륨이 큰 요소는 상한 지정.
2. 이미지 단계: **표정 시트**(눈 감김, 입 5모음, 감정)를 같은 화풍으로 함께 생성.
3. 3D 단계: 얼굴 부위 UV를 한 섬으로 유지, 눈/눈꺼풀/입을 분리 부품으로 요청(보장은 안 됨).
4. 리깅 직후: 옷 웨이트 자동 점검(몸통이 다리 본에 묶였는지), 후드·소매 볼륨 점검.
5. 스프링: 치마 줄 수 16+, 허벅지/어깨/가슴 충돌체를 템플릿화.
6. 표정: 셰이프 키(입·턱·볼·눈썹) + 눈꺼풀 덮개 방식 시험 후 ARKit 이름으로 연결.
